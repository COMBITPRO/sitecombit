# Комбит Про — лендинг

Статический сайт на Astro. Для локальной разработки:

```sh
npm install
npm run astro -- dev --background
```

Production-сборка создаётся командой `npm run build` в каталоге `dist`.

## Управление контентом

Тексты, контактные данные, карточки и изображения вынесены в `src/content/site.json`. Заказчик может редактировать их через бесплатный [Pages CMS](https://pagescms.org/), не работая с исходным кодом:

1. Разместите репозиторий на GitHub и откройте [Pages CMS](https://app.pagescms.org/).
2. Авторизуйтесь через GitHub и предоставьте сервису доступ к этому репозиторию.
3. Выберите раздел «Содержимое сайта», внесите изменения и нажмите Save.
4. Pages CMS создаст коммит в репозитории. После коммита в master workflow GitHub Actions проверит, пересоберёт и опубликует сайт на GitHub Pages. Подключённый автодеплой Layero может параллельно обновить резервную копию.

Конфигурация редактора находится в `.pages.yml`. В ней доступны только контентные поля; дизайн, стили и компоненты через CMS не редактируются. Изображения, загруженные заказчиком, сохраняются в `public/images`.

Перед передачей доступа рекомендуется создать для заказчика отдельную учётную запись GitHub и выдать ей доступ только к этому репозиторию.

### Форматирование текста

Все содержательные текстовые поля в разделе «Содержимое сайта» открываются в WYSIWYG-редакторе Pages CMS: описания блоков, вводные и заключительные абзацы, карточки услуг, списки отраслей и заказчиков, проекты, текст контактов и подвал.

Чтобы отформатировать только часть текста, выделите нужное слово или фразу в редакторе и выберите действие на панели инструментов: **B** — жирный, *I* — курсив, ссылка, список и т. п. Форматирование применяется только к выделенному фрагменту, а не ко всему текстовому блоку. Если ничего не выделено, выбранный стиль будет применён к последующему вводу.

Нажатие Enter создаёт новый абзац. Не используйте форматирование для имитации дизайна сайта: размеры шрифта, цвета, отступы и вид заголовков задаются в коде, чтобы сайт сохранял единый и корректный вид на компьютерах и телефонах.

Короткие служебные поля — заголовки страниц, пункты меню, кнопки, телефоны, адреса e-mail, ссылки, технические идентификаторы и альтернативные тексты изображений — намеренно остаются обычными полями. Их форматирование не поддерживается, поскольку HTML в этих местах может повредить навигацию, форму, поисковую выдачу или доступность сайта.

Pages CMS сохраняет форматирование в `src/content/site.json` как HTML. Не редактируйте этот HTML вручную: меняйте текст через визуальный редактор и нажимайте Save. CMS создаст коммит, после чего подключённый автодеплой пересоберёт сайт.

## Форма обратной связи

Заявки отправляются из собственной формы сайта в Formspree через AJAX. Пользователь остаётся на лендинге, а Formspree пересылает данные на подтверждённые адреса электронной почты.

Для подключения и локального тестирования:

1. Зарегистрируйтесь на [Formspree](https://formspree.io/) и создайте новую форму.
2. Добавьте и подтвердите адреса получателей уведомлений.
3. Скопируйте endpoint вида `https://formspree.io/f/xxxxxxxx`.
4. Создайте локальный `.env` на основе `.env.example` и укажите endpoint в `PUBLIC_FORMSPREE_ENDPOINT`.
5. Перезапустите dev-сервер и отправьте тестовую заявку.

Если endpoint не задан, кнопка отправки отключена. Секретов в этой переменной нет: Formspree специально выдаёт публичный адрес для клиентских форм.

## Основной хостинг — GitHub Pages

Репозиторий: [COMBITPRO/sitecombit](https://github.com/COMBITPRO/sitecombit), ветка публикации: master. Основной адрес: https://kombit.pro/ (домен зарегистрирован в Рег.ру). Публикация рассчитана на публичный репозиторий; его видимость меняет владелец. Адрес https://combitpro.github.io/sitecombit/ — технический адрес Pages до подключения домена.

Автопубликация описана в [.github/workflows/pages.yml](.github/workflows/pages.yml). Workflow запускается после push в master и вручную через Actions → Deploy to GitHub Pages → Run workflow. Он устанавливает Node.js 22 и зависимости через npm ci, собирает сайт, проверяет SEO и локальные ресурсы, загружает dist и публикует проверенный артефакт. Изменения из Pages CMS проходят тот же процесс. Папку dist коммитить не нужно; ветка gh-pages не используется.

### Первое включение

1. Перевести COMBITPRO/sitecombit в публичный режим. Для публичного репозитория GitHub Pages доступен на GitHub Free; дополнительных платных тарифов для размещения не требуется.
2. В Settings → Pages → Build and deployment выбрать Source: GitHub Actions.
3. В Settings → Secrets and variables → Actions → Variables добавить PUBLIC_FORMSPREE_ENDPOINT с endpoint существующей формы. Без него сайт публикуется, но отправка заявок отключена. Это публичный адрес, не секрет. Если в Formspree ограничены домены, разрешить kombit.pro и при необходимости www.kombit.pro.
4. Подключить kombit.pro по инструкции ниже. SITE_URL можно не задавать: по умолчанию конфигурация и workflow используют https://kombit.pro/. Если repository variable SITE_URL уже существует, установить https://kombit.pro/ или удалить переопределение. Префикс ресурсов workflow получает из actions/configure-pages.
5. Отправить изменения в master. Проверить успешные jobs build и deploy в Actions, затем открыть адрес из Settings → Pages.
6. Проверить CSS, изображения, файлы, якорное меню и отправку тестовой заявки; убедиться, что в canonical и sitemap указан основной адрес. Включить Enforce HTTPS в Settings → Pages, когда настройка доступна.

### Переменные сборки и адреса ресурсов

- SITE_URL — полный основной адрес лендинга для canonical, Open Graph, JSON-LD и карты сайта. Основное и стандартное значение — https://kombit.pro/.
- SITE_BASE_PATH — путь, по которому текущая копия опубликована на хостинге. Для стандартного Pages этого репозитория — /sitecombit/, для собственного домена и Layero — /. В GitHub Actions определяется настройками Pages, отдельная repository variable не нужна.
- PUBLIC_FORMSPREE_ENDPOINT — endpoint формы.

CMS продолжает хранить адреса вида /images/... и /documents/.... Префикс добавляется во время сборки; менять контент при переезде или подключении домена не требуется. Внешний вид и одностраничная структура сохраняются.

Проверка Pages-сборки локально в PowerShell (в текущем терминале не должно быть других значений этих переменных):

~~~powershell
$env:SITE_URL = 'https://kombit.pro/'
$env:SITE_BASE_PATH = '/'
npm run build
npm run test:seo
Remove-Item Env:SITE_URL, Env:SITE_BASE_PATH
~~~

### Подключение kombit.pro через Рег.ру

1. В настройках организации COMBITPRO открыть Pages → Add a domain и добавить kombit.pro. GitHub покажет TXT-запись подтверждения владения: имя вида _github-pages-challenge-COMBITPRO и индивидуальное значение. Скопировать точные имя и значение из GitHub в DNS-зону, дождаться проверки и нажать Verify. TXT-запись после подтверждения сохранить. [Инструкция подтверждения](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).
2. В репозитории открыть Settings → Pages → Custom domain, указать kombit.pro и сохранить. Этот шаг выполнить до переключения A/CNAME-записей сайта.
3. В Рег.ру открыть домен kombit.pro → DNS-серверы и управление зоной → Изменить и перейти к ресурсным записям. Этот интерфейс используется, если авторитетные DNS — ns1.reg.ru/ns2.reg.ru. Если домен делегирован другим DNS-серверам, записи нужно менять у действующего DNS-провайдера; менять NS для подключения к Pages не требуется.
4. Установить записи ниже. Для @ заменить прежние A-записи сайта на четыре адреса GitHub. Старые AAAA, указывающие на другой хостинг, удалить или заменить адресами IPv6 из инструкции GitHub. Для www заменить конфликтующие A/AAAA/CNAME одной CNAME-записью. Сохранить MX и TXT почты, SPF, DKIM, DMARC и подтверждений владения. Домену не нужна CNAME-запись на @ и не нужен путь /sitecombit/ в DNS.

| Тип | Поддомен / имя | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | combitpro.github.io. |

Значения сверены с [инструкцией GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Работа с зоной: [инструкция Рег.ру](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete).

5. Дождаться успешной DNS-проверки в Settings → Pages. Изменения DNS и готовность HTTPS могут занять до 24 часов. Включить Enforce HTTPS, когда сертификат готов. При основном домене kombit.pro GitHub настроит переход с www.kombit.pro на основной домен при корректных DNS-записях обоих имён.
6. Запустить Actions → Deploy to GitHub Pages → Run workflow для master. Configure Pages передаст базовый путь /, а сборка будет использовать основной адрес https://kombit.pro/. Изменение домена в настройках само по себе не гарантирует пересборку нашего артефакта.
7. Проверить https://kombit.pro/, https://www.kombit.pro/, https://kombit.pro/robots.txt, https://kombit.pro/sitemap.xml, изображения, PDF/DOCX/XLSX и форму. В canonical, Open Graph и JSON-LD должен быть kombit.pro.
8. На резервном Layero задать SITE_URL=https://kombit.pro/ и SITE_BASE_PATH=/, затем выполнить новый деплой.

При публикации через GitHub Actions файл CNAME не требуется: GitHub использует домен из Settings → Pages. Создавать файл CNAME в public для этого workflow не нужно. DNS и настройки GitHub необходимо выполнить отдельно: изменение исходников их не применяет.

## Резервный хостинг — Layero

Layero остаётся второстепенной копией из того же репозитория. Команда сборки — npm run build, каталог публикации — dist. Настройте переменные окружения сборки:

- SITE_URL=https://kombit.pro/ — основной адрес на GitHub Pages, а не адрес Layero.
- SITE_BASE_PATH=/ — файлы резервной копии доступны от корня её домена.
- PUBLIC_FORMSPREE_ENDPOINT — тот же endpoint формы.

После изменения переменных выполнить новый деплой. Так Layero загружает свои ресурсы, а canonical указывает на основную площадку. Резервный адрес не отправлять на индексацию. Проверка https://combit-sitecombit.layero.app/ 21 октября 2026 года обнаружила заголовок X-Robots-Tag: noindex, nofollow; для резервной копии запрет можно сохранить. Он не должен присутствовать на основном сайте.

Резервная копия не обеспечивает автоматическое переключение при сбое GitHub Pages: для этого потребуется отдельно переключить домен/DNS на Layero и пересобрать резервную копию с актуальными переменными.

## Поисковая оптимизация и запуск

По умолчанию SITE_URL равен https://kombit.pro/ на обеих площадках. Этот адрес используется в canonical, Open Graph, JSON-LD и карте сайта. Карта сайта содержит только главную страницу лендинга.

После запуска основного адреса:

1. Убедиться, что он отвечает 200, работает HTTPS, отсутствует noindex, canonical указывает на основной URL.
2. Открыть https://kombit.pro/sitemap.xml: единственный адрес в карте должен быть https://kombit.pro/.
3. Добавить kombit.pro в Яндекс Вебмастер и Google Search Console, подтвердить права доступным для этого адреса способом и отправить sitemap и главную на обход.
4. Указать основной адрес в карточке компании и официальных профилях.

При адресе с /sitecombit/ файл robots.txt физически находится в /sitecombit/robots.txt. Поисковики читают robots.txt из корня домена; этот файл проекта не управляет всем доменом combitpro.github.io. Для этого адреса отправляйте карту сайта напрямую через поисковые кабинеты. На собственном домене файл будет доступен в корне как обычно.

Официальные инструкции: [Astro на GitHub Pages](https://docs.astro.build/en/guides/deploy/github/), [workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [доступность и ограничения Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

### SEO в рамках одностраничного лендинга

Сайт сохраняет согласованные блоки, внешний вид и якорную навигацию. Отдельных страниц оборудования и услуг нет. Заголовок и описание для поиска редактируются в разделе «Поисковая выдача» Pages CMS. Название компании, контакты, модели, характеристики и услуги используются из существующего контента в src/content/site.json.

Компонент src/components/Seo.astro формирует метаданные, разметку Organization, WebSite, WebPage и каталог оборудования по существующим карточкам. Адреса моделей в разметке ведут к якорям на этой же странице. Это описание опубликованного контента, а не скрытые тексты с ключевыми словами. Оборудование и услуги уже присутствуют в HTML сборки и не требуют отдельного запроса для загрузки.

В карте сайта присутствует только главная страница. Якорные разделы не объявляются самостоятельными страницами. Поисковое продвижение опирается на название компании, существующие описания радарных уровнемеров Лимако, моделей УЛМ, применения в резервуарах и услуг внедрения и обслуживания. Частотность и конкуренция запросов не измерены; позиции оцениваются после публикации и индексации.

Проверка: npm run build, затем npm run test:seo. Для проверки canonical и карты сайта задайте SITE_URL перед сборкой. Проверки контролируют метаданные, разметку, единственную HTML-страницу, адреса файлов и карту сайта.
