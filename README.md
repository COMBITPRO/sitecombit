# Комбит Про — лендинг

Статический сайт на Astro. Для локальной разработки:

```sh
npm install
npm run astro -- dev --background
```

Production-сборка создаётся командой `npm run build` в каталоге `dist`.

## Управление контентом

Тексты, контактные данные, карточки и изображения вынесены в `src/content/site.json`. Заказчик может редактировать их через бесплатный [Pages CMS](https://pagescms.org/), не работая с исходным кодом:

1. Разместите репозиторий на GitHub и откройте [Pages CMS](https://app.pagescms.org/).
2. Авторизуйтесь через GitHub и предоставьте сервису доступ к этому репозиторию.
3. Выберите раздел «Содержимое сайта», внесите изменения и нажмите Save.
4. Pages CMS создаст коммит в репозитории. Если Layero подключён к этому репозиторию с автоматическим деплоем, сайт пересоберётся после коммита.

Конфигурация редактора находится в `.pages.yml`. В ней доступны только контентные поля; дизайн, стили и компоненты через CMS не редактируются. Изображения, загруженные заказчиком, сохраняются в `public/images`.

Перед передачей доступа рекомендуется создать для заказчика отдельную учётную запись GitHub и выдать ей доступ только к этому репозиторию.

### Форматирование текста

Все содержательные текстовые поля в разделе «Содержимое сайта» открываются в WYSIWYG-редакторе Pages CMS: описания блоков, вводные и заключительные абзацы, карточки услуг, списки отраслей и заказчиков, проекты, текст контактов и подвал.

Чтобы отформатировать только часть текста, выделите нужное слово или фразу в редакторе и выберите действие на панели инструментов: **B** — жирный, *I* — курсив, ссылка, список и т. п. Форматирование применяется только к выделенному фрагменту, а не ко всему текстовому блоку. Если ничего не выделено, выбранный стиль будет применён к последующему вводу.

Нажатие Enter создаёт новый абзац. Не используйте форматирование для имитации дизайна сайта: размеры шрифта, цвета, отступы и вид заголовков задаются в коде, чтобы сайт сохранял единый и корректный вид на компьютерах и телефонах.

Короткие служебные поля — заголовки страниц, пункты меню, кнопки, телефоны, адреса e-mail, ссылки, технические идентификаторы и альтернативные тексты изображений — намеренно остаются обычными полями. Их форматирование не поддерживается, поскольку HTML в этих местах может повредить навигацию, форму, поисковую выдачу или доступность сайта.

Pages CMS сохраняет форматирование в `src/content/site.json` как HTML. Не редактируйте этот HTML вручную: меняйте текст через визуальный редактор и нажимайте Save. CMS создаст коммит, после чего подключённый автодеплой пересоберёт сайт.

## Форма обратной связи

Заявки отправляются из собственной формы сайта в Formspree через AJAX. Пользователь остаётся на лендинге, а Formspree пересылает данные на подтверждённые адреса электронной почты.

Для подключения и локального тестирования:

1. Зарегистрируйтесь на [Formspree](https://formspree.io/) и создайте новую форму.
2. Добавьте и подтвердите адреса получателей уведомлений.
3. Скопируйте endpoint вида `https://formspree.io/f/xxxxxxxx`.
4. Создайте локальный `.env` на основе `.env.example` и укажите endpoint в `PUBLIC_FORMSPREE_ENDPOINT`.
5. Перезапустите dev-сервер и отправьте тестовую заявку.

Если endpoint не задан, кнопка отправки отключена. Секретов в этой переменной нет: Formspree специально выдаёт публичный адрес для клиентских форм.

## Деплой на Layero

Проект остаётся статическим и не зависит от конкретного хостинга. В Layero добавьте `PUBLIC_FORMSPREE_ENDPOINT` как переменную окружения сборки и выполните новый деплой. На бесплатном тарифе сайт будет доступен на поддомене `*.layero.ru`; собственный домен требует платного тарифа Layero.

## Поисковая оптимизация и запуск

В переменных сборки Layero задайте `SITE_URL` — основной публичный адрес, например `https://company.ru`, без пути и параметров, затем пересоберите сайт. При смене домена измените эту переменную и выполните новый деплой. Для локальной сборки переменную можно задать в `.env`.

При заданном `SITE_URL` сайт получает canonical, полный адрес в Open Graph, разметку WebSite и `sitemap.xml` с единственной главной страницей. Разметка Organization использует название компании и контакты, опубликованные на странице. `robots.txt` разрешает обход и ссылается на карту сайта. Без `SITE_URL` сборка работает, но адресные метаданные и карта сайта не создаются: локальный или выдуманный домен не попадёт в индекс.

Проверка временного адреса `https://combit-sitecombit.layero.app/` 21 октября 2026 года обнаружила HTTP-заголовок `X-Robots-Tag: noindex, nofollow` на главной странице. Его отдаёт опубликованное окружение; в исходниках сайта этот запрет отсутствует. Перед индексацией основного домена проверьте настройки Layero или обратитесь в поддержку: на рабочем адресе не должно быть `noindex` ни в HTTP-заголовках, ни в HTML. Разрешение обхода в `robots.txt` не отменяет этот запрет.

После подключения постоянного домена:

1. Проверить HTTPS, открытие сайта и CSS, работу формы и документов. Настроить перенаправление альтернативных адресов на основной, если это поддерживает хостинг.
2. Убедиться, что главная отвечает 200, отсутствует `noindex`, canonical указывает на основной адрес, а `/robots.txt` и `/sitemap.xml` доступны.
3. Добавить домен в Яндекс Вебмастер и Google Search Console, подтвердить права, отправить карту сайта и запросить обход главной страницы.
4. В существующей карточке компании в Яндекс Бизнесе и других официальных профилях указать новый сайт. Название, телефон и адрес должны совпадать с сайтом. Если старый домен уже используется компанией, сначала согласовать переезд и перенаправления.
5. Отслеживать индексацию и показы по названию компании и тематическим запросам. Первая позиция и сроки индексации не гарантируются.

### SEO в рамках одностраничного лендинга

Сайт сохраняет согласованные блоки, внешний вид и якорную навигацию. Отдельных страниц оборудования и услуг нет. Заголовок и описание для поиска редактируются в разделе «Поисковая выдача» Pages CMS. Название компании, контакты, модели, характеристики и услуги используются из существующего контента в src/content/site.json.

Компонент src/components/Seo.astro формирует метаданные, разметку Organization, WebSite, WebPage и каталог оборудования по существующим карточкам. Адреса моделей в разметке ведут к якорям на этой же странице. Это описание опубликованного контента, а не скрытые тексты с ключевыми словами. Оборудование и услуги уже присутствуют в HTML сборки и не требуют отдельного запроса для загрузки.

В карте сайта присутствует только главная страница. Якорные разделы не объявляются самостоятельными страницами. Поисковое продвижение опирается на название компании, существующие описания радарных уровнемеров Лимако, моделей УЛМ, применения в резервуарах и услуг внедрения и обслуживания. Частотность и конкуренция запросов не измерены; позиции оцениваются после публикации и индексации.

Проверка: npm run build, затем npm run test:seo. Для проверки canonical и карты сайта задайте SITE_URL перед сборкой. Проверки также подтверждают, что видимые блоки и стили соответствуют согласованному лендингу.
